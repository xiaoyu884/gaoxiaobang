# 高校邦助手：兼容性与发布蓝图

更新日期：2026-10-08。本文合并此前六项公开发布工作流与近期五项改进计划，作为后续实现和验收的依据。仓库已经公开；公开可见、发布可安装版本、验证浏览器兼容性及明确代码授权是不同事项。

## 当前基线与问题

- 执行控制已在 PR #1 合并到 `main`：1.4.0 默认暂停，三个模块默认关闭，支持开始 / 重试、暂停及同标签页授权恢复。
- 最近一次回归验证为 273 项断言通过。真实 Firefox 已验证执行控制；隔离的 Firefox 本地页面已验证取消请求、忽略迟到答案及阻止后续提交确认。
- 尚未用 1.4.0 完整处理一门未完成课程，尚未验证 Windows Edge 的安装与完整运行。此前 1.3.7 的真实课程记录不能替代这些验证。
- 用户反馈：Edge 安装困难；下一任务偶发不推进、稍后又恢复；讨论偶发未完成。这些是待复现报告，不能直接归因为 Edge 或网络。
- 已确认代码仍默认使用旧模型名 `deepseek-chat`，模型设置也会被持久保存；仅改变默认值不能修复所有已有安装。
- 已确认导航多处等待约 15 秒后要求手动重试；讨论发帖后立即读取回复列表确认。延迟加载和延迟可见是待验证的原因。
- 已启用的讨论阶段未完成会阻止自动导航。因此讨论故障与导航故障可能相关，排查时必须区分“导航没有执行”与“导航执行后页面没有切换”。

## 优先级总表

P0：优先处理的兼容性问题或授权事项。P1：可靠发布所需的安装、诊断与运行改进。P2：汇总验证和发布。表中顺序是默认执行顺序；授权核对可与工程工作并行，讨论与导航的实际修复顺序可由诊断证据调整。

|---|---|---|---|---|---|
| 1 | P0 | 授权与来源核对 | 原工作流 1 | 未完成；此前结论需重新核对 | 有可记录的使用、修改、再分发依据及相应声明 |
| 2 | P0 | DeepSeek 兼容性修复 | 新改进 1 | 未完成；旧默认值已确认 | 新安装、旧设置迁移和响应处理通过验证 |
| 3 | P1 | 页面状态与诊断导出 | 新改进 3 | 未完成 | 为偶发问题提供可解释、可脱敏的证据 |

## 1. 授权与来源核对（P0，并行推进）

此前检查指出两份已署名上游代码的授权依据不充分。这是历史评估，不是对上游当前状态的新核验，也不是法律结论。

- 重新核对来源、上游声明、许可证和继承代码，记录哪些部分来自上游、哪些是本项目新增。
- 在适用授权明确后添加相应 `LICENSE` 与第三方声明，并保留作者署名；不将公开仓库或署名本身视为完整的再分发授权。
- 如需联系作者，先准备请求内容；实际发送须由用户明确授权。仅保存这份蓝图不授权发送消息。
- 如果相关权限始终无法确定，提出独立实现方案，并评估已有 Git 历史中的继承代码。替换实现不自动解决旧历史的来源问题；新仓库或历史处理另行决定，不在本计划中自动执行。

验收：来源清单、所依据的授权记录及适用声明可由维护者核对。工程修复可继续；发布许可和授权保证必须与记录一致。

## 2. DeepSeek 兼容性修复（P0）

- 默认模型改为当前官方 API 名称 `deepseek-flash`；模型名称不是网页聊天产品名称。
- 对已保存的已知退役模型名提供明确迁移及提示；保留 API Key 与自定义模型选择，不把所有模型值强制覆盖为新默认值。
- 显式选择思考模式和输出预算。现有请求只允许单选 4、多选 8 个输出 token；不能假设直接换模型名即可兼容默认思考模式。
- 检查响应的结束原因、空内容、截断和选项合法性，保留严格答案解析；不把推理文本当作答案。
- 区分密钥错误、模型不可用、额度、限流、网络失败与超时，给出对应处理提示。避免盲目重复请求或静默切换到其他收费模型。
- 提供用户主动触发的连接测试；若会调用收费 API，应说明这一点。配置或迁移本身不启动课程自动化。

验收：新安装、旧默认迁移、自定义模型保留、单选 / 多选、空响应 / 截断 / HTTP 错误均有测试；无效答案不触发提交。真实 API 检查与模拟响应检查分别记录。

## 3. 页面状态与诊断导出（P1）

- 控制面板展示当前阶段、等待对象和停止原因，例如“等待目录”“讨论待确认”“测验结果未确认”“下一任务链接缺失”“页面切换超时”。不能仅显示“已启动”。
- 按操作记录开始、响应、确认及路由变化，区分主动暂停、可恢复错误和等待手动操作。
- 增加用户主动导出的诊断摘要：脚本版本、浏览器 / 管理器版本（无法自动读取时允许补填）、模块、阶段、时间顺序及错误类别。
- 导出不包含 API Key、Cookie、令牌、题目、回复正文或可识别账号信息；不要直接导出原始网络响应、完整 URL 或原始课程标识。定位标识仅保留经审查的匿名形式。
- 不自动上传日志，不要求用户发布整个控制台截图。维护者用脱敏诊断与必要的复现步骤建立本地测试样例。

验收：每类停止原因能在面板识别；诊断能区分讨论阻塞与导航失败；导出经过敏感字段检查，开关或暂停不会改变诊断中的事实。

## 4. Edge 安装与更新（P1）

- README 提供明显的安装入口，链接到可安装的 `.user.js` 文件；注明 Tampermonkey 是前置条件。
- 增加 Windows Edge 图文步骤：安装管理器、允许执行用户脚本、安装本脚本、打开正确课程域名、看到暂停面板、勾选模块并开始。
- 按实际浏览器版本说明“允许用户脚本”开关或开发者模式；第三方商店权限只在使用该安装来源时说明，不要求所有用户开启无关权限。
- 常见失败分别排查：管理器未安装 / 禁用、脚本执行权限不足、站点权限、脚本未保存 / 禁用、进入非匹配域名、学校设备策略限制。
- 增加项目主页、支持地址及明确的 `@downloadURL` / `@updateURL`；保持已有脚本身份与存储兼容，避免安装成第二份脚本。
- 提供明确的手动导入 / 替换兜底步骤与升级验证方法。先确定稳定发布渠道，再指向更新源，避免让用户自动接收未经验证的分支版本。

验收：干净 Windows Edge + Tampermonkey 实际安装成功、显示暂停面板；更新同一脚本后设置与记录保留，只有一份启用脚本；无权限时文档能定位问题。

## 5. 持续检查（P1）

- 配置 GitHub Actions，在 PR 和目标分支变动时运行 JavaScript 语法检查及现有回归测试。
- 使用锁文件和 `npm ci`，选择符合当前 jsdom 要求的受支持 Node.js 版本；工作流不需要真实账号或 API Key。
- 新增测试围绕实际故障和状态不变量，覆盖延迟数据、请求取消、重复回调与恢复；不只复述实现。
- 明确模拟测试不验证 Edge 的扩展权限、真实课程接口或真实模型可用性。CI 结果与人工浏览器验收分别记录。

验收：正常 PR 检查通过；故意引入语法或回归错误时检查失败，恢复后通过；CI 不访问真实课程和 DeepSeek，也不输出秘密。

## 6. 讨论确认与恢复（P1）

- 先复现并分类：目录 / 专题 ID 未就绪、回复分页、当前用户识别、空讨论、会话失效、限流、提交失败及提交后延迟可见。
- 检查实际接口分页能力，不能仅凭第一页没有当前用户就断言尚未发帖。
- 将“待处理”“提交中”“已发送待确认”“已确认”“需人工判断”区分开。只有确认当前用户回复后才标记完成。
- 对回复读取和确认进行有上限的重试与退避。提交后的超时或连接中断属于结果不确定，应先核对回复，不立即重发 POST。
- 没有可用评论时显示待手动处理，不伪造成功、不自动生成新回复。恢复或刷新后同样要先核对服务器记录。
- 与多标签页保护衔接，避免两个执行者同时判定“未回复”并重复提交。

验收：延迟可见和模拟“服务器已接受、客户端超时”不会造成重复发帖；分页中已有回复能识别；暂停阻止重试；未确认专题保持待处理并明确解释导航为何被阻塞。

## 7. 下一任务导航可靠性（P1）

- 依据诊断确认故障发生在完成识别、阶段依赖、目录加载、目标选择、发起切换还是新页面就绪。
- 增加目录晚到、结果晚到、复用 DOM、同页路由变化及超出原等待时间的复现样例。把数据就绪与任务完成分开验证。
- 在有效授权内等待或恢复可恢复的读取 / 导航操作，并设置上限与退避；避免无限刷新、重复点击和跳过最早未完成任务。
- 导航后核对目标课程 / 章节及页面就绪。发起点击或改变 URL 不能直接记为成功；不要把旧页面结果用于新任务。
- 结果不确定时停留并显示可操作原因。保留同站点、同课程限制；书面作业仍只打开入口并交给用户完成。

验收：延迟加载样例中重复运行至少 20 次，均准确推进一次；已完成任务不重开、旧回调不操作新任务、讨论未确认时不跳过、暂停后不继续导航。真实浏览器验证与模拟结果分别记录。

## 8. 多标签页保护（P1）

- 锁按站点、账号、课程隔离；不同课程不互相阻塞。
- 每次运行具有唯一所有者标识，通过管理器共享存储协调，并使用心跳 / 租约恢复关闭、崩溃或长期失联的执行者。
- 核对所选存储 API 是否支持所需的竞争处理；仅“先读取、再写入”不能保证两标签页同时开始时只有一个胜出。
- 在外部副作用前再次核对锁归属；失去归属立即暂停。页面说明哪个运行正在占用，提供明确恢复流程。
- 同标签页导航、刷新与暂停的锁生命周期必须清楚。后台标签页计时器可能被节流，不能只凭一次心跳延迟就允许另一标签页重复执行。

验收：两标签页同时开始、后台节流、关闭 / 崩溃、刷新、不同课程和账号切换均有测试；同一课程不会出现两个已获授权的执行者，恢复不重复发帖或提交。

## 9. 浏览器验证、文档与版本发布（P2）

- 最低测试矩阵：Windows Edge + Tampermonkey、现有 Firefox + Tampermonkey。记录操作系统、浏览器、管理器和脚本的实际版本。
- 覆盖干净安装、旧版升级、默认暂停、模块授权、API 配置、刷新、课程切换、手动测验完成后的推进、讨论延迟确认、网络中断和多标签页竞争。
- 验证会话过期、HTTP 401 / 403 / 429、模型不可用及页面数据超时；可能影响账号的副作用优先使用隔离页面，真实课程操作须在明确允许的测试范围内进行。
- 对至少一门未完成课程验证所启用模块的完整流程；记录不能覆盖的课程类型和站点，不把某一校区测试推广为所有高校邦站点保证。
- 更新 README、安装 / 故障排查文档、变更记录及支持矩阵；写清已验证、失败、受阻、未测试的范围。
- 发布带版本号的脚本与说明，并确认安装 / 更新链接指向已验证内容。若仍缺少真实 Windows Edge 或完整课程验证，标注测试版及具体限制。

验收：CI 通过，规定浏览器检查完成，遗留问题明确记录；更新保留设置；用户能从安装到解释停止原因。不能以“后来成功一次”代替可靠性验收。

## 交付顺序与实施约定

1. 并行核对授权；首先交付模型兼容性修复。
2. 交付诊断、Edge 安装指南与安装 / 更新入口；建立 CI。
3. 用实际故障证据修复讨论和导航；实现多标签页保护，再联合测试副作用与恢复。
4. 完成 Windows Edge 与 Firefox 验收、文档和版本发布。

每项工程工作采用独立、可审阅的变更，修复与文档相互对应。按仓库约定保留用户修改，提交前列出文件与提交说明、确认验证和审查结果，推送前列出远端、分支、待推送提交及工作区状态。实际 Git 操作、合并、对外联系和发布依当次用户授权执行；蓝图本身不授予这些权限。
